## 0. 范围与方法

- **范围**：tag v3.4.0（f18e3bc, 10/1）.. HEAD 共 **62 个提交**（v3.4.1→v3.7.0），另对 v3.4.0

  合并（459505e）内容剔除出审查面（非本仓改动）。
- **方法**：每个修复回溯三件套——①当时原始证据（DB 取证/推理/用户决策）②现代码+测试锁
  是否仍成立 ③后续真机数据支持还是推翻。可做实验的不做推理（本轮新增探针测试 1 个）。
- **判定四级（不用二元，防错杀）**：
  A 实锤保持｜B 有效但标签/叙事要改｜C 未证伪但存在缺口或证据弱（争议项，用户终审）｜
  D 确实修错需回滚。
- **规避的误判**：不按结果倒推（outcome bias）；机制假说≠现象实锤；防御性/行为变更/决策
  不与"修复对错"混判；UI/文案类轻审并如实标注覆盖面。

## 3. 争议项详情（C 类，证据 vs 反证 vs 建议 —— 待用户终审）

### C1【真实缺口，探针实证】新鲜 run 超窗时 round1 无兜底

- **证据**：`AgentLoop` 硬裁门为 `usageObserved && rawEstimate ≥ trimWindow`，而
  `usageObserved` 每 run 从 false 起步；round1 拿不到 provider usage 前，compact 因
  `inputTokens==null` 早退、trim 与 M1.2 降级链同时被门挡住。
- **实验（本轮新增探针 `freshRunOversizedHistorySendsRound1UntrimmedAndTrimsFromRound2`）**：
  - ✅ 断言过：round1 把 ≥700k 字符的巨型历史**原样发出**（未经任何裁剪）；
  - ✅ 断言过：round2 拿到 usage 后 `HistoryTrimmed` 正常触发——**链路 round2 起有效**。
- **反证/缓和**：失败形态是结构化 `CONTEXT_OVERFLOW` 错误（非崩溃），与 Trimmer 文档宣称
  的"防止超窗请求发出"仍有落差；原始 3,278,699 案例若落在 round1，现有链救不回来。
- **建议（待拍板）**：trim 门放宽为 `rawEstimate ≥ trimWindow` 即可（去掉 usageObserved
  前置）——round2 本来就用同一估量口径判定，估量可信度不随轮次变化；探针测试转为回归锁。
  改动量约几行 + 测试调整，属正收益。**未擅自修改，等终审。**

### C2【叙事修正，非代码错误】

  注意：**记忆敏感性自 1328751（3.4.3）起从未摇摆**，与 M1.4 方向始终一致。
- **② 29ee2ff（v3.4.9 "根因修复——视觉管线缩放"）**：三拆——
  - 现象（x/y 同比例乘性偏差 0.942/0.959、2877×0.942≈2711）= **两轮 DB 实测，实锤**；
  - 机制（服务商视觉管线缩放）= **黑箱不可观测的假说，未证伪也未证实**（方案审查曾质疑）；
  - 手段（prompt 写 6%）= 后续真机证明**首中率未改善**，已由 M1.1 删除、locate 替代。
  **判定：现象 A 级、机制 C 级、"根因修复"标签 B 级。** 历史 release note 不回改（保持
  档案原貌），以本报告 + INVARIANTS 的 Changelog 规范（prompt 约束禁止再称根因）为准。
