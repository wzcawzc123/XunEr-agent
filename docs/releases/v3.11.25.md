# v3.11.25 — 稳定性体检批次 B：中危八项修复（压缩风暴/出站口径/守卫覆盖/journal/rewrite/竞态/工具交错）

## 背景

延续批次 A（v3.11.24，高危五项），本版处理体检发现的中危项 C1/C2/C4-C9 共 8 项；
C3（round-1 校准盲区 + CONTEXT_OVERFLOW 自动恢复）为 ask-first 项，涉及既有测试契约
（"溢出不自动重放"是防止重复 GUI 副作用的**有意设计**），保留现状待确认，未纳入本版。

## 根因与修复

### C1 — compactEnd 保留预算口径 + 降幅校验不与触发线对齐（压缩风暴残留）
- **根因**：`compactEnd` 用 raw 成本对比窗口单位的 retain 预算——cal<1 时实际保留仅
  cal×0.16W（缩水 2~4 倍）、cal>1 时可超 trigger；`MIN_REDUCTION_PERCENT` 只挡相对降幅，
  挡不住"压完仍高于触发线"（cal>1 时成功路径上的压缩风暴）。
- **修复**：`AgentContextCompactor` 增加 `calibration` 参数（由 `AgentContextSession` 传入），
  `compactEnd` 成本乘校准换算；降幅校验后新增绝对校验 `after×cal < trigger` 否则拒绝。
- **测试**：既有 `summaryInputIsBoundedAndDropsOldestBeyondBudget` 因保留口径变化不再触发
  截断——放大轮次/消息长度使校准口径下摘要输入仍超预算，保留其验证意图。

### C2 — 裁剪分支绕过 prune/strip（纯文本模型裁剪轮发图→400）
- **根因**：`AgentLoop` 裁剪后 `requestMessages` 仅重新 project，丢弃了 `pruneRequestMessages`
  与 `stripImagesForTextOnlyModel`——`supportsVision=false` 模型在裁剪轮会把图片块发出去（必 400）。
- **修复**：裁剪后重放两道出站变换（幂等、只改出站副本，不影响缓存前缀一致性）。

### C4 — Roleplay 投影未计入 trim 固定开销
- **根因**：`systemEstimate` 只算裸 system 消息；roleplay 的 persona/worldbook/depth/postHistory
  注入（可达数万 token）漏计 → `limit` 偏大 → 保留过多 → `afterTrimTokens` 仍超线 →
  `CONTEXT_EXHAUSTED` 死角。
- **修复**：`systemEstimate` 改为"投影后请求 − 投影后历史"的净固定开销；非 roleplay 时
  投影返回原引用，差值与旧行为等价。

### C5 — regenerate/resume 绕过容量守卫
- **根因**：R2 守卫只挂在 `sendCurrentMessage` 编辑分支；`regenerateMessage`（角色+普通两条路径）
  与 `resumeInterruptedRunNow` 携带同等规模前缀却无守卫 → 超窗请求原样发出 → Runtime 运行失败。
- **修复**：提炼共享 `guardHistoryPrefix`（与会话绑定模型同源窗口、固定开销保底 24K），
  三处入口统一调用；编辑分支拦截时照旧 `cancelMessageEdit()`。

### C6 — 编辑首条消息 journal 不截断（幽灵分支膨胀）
- **根因**：`sendCurrentMessage` 中 `journal = journalPrefix?.takeIf { it.isNotEmpty() } ?: 全量`——
  编辑**首条**消息时 journalPrefix 为空 → 回退全量 journal（含被编辑抛弃的旧正文与旧后缀）；
  二次编辑按 journal 定位时把幽灵分支重新带进历史，逐次编辑逐次膨胀。
- **修复**：与 history 同语义"空即空"，`journal = journalPrefix ?: homeState.journal`。

### C7 — rewrite ref 结果不 apply 不 ACK（pendingRewrites 残留）
- **根因**：`applyRunResult` rewriting 分支只在 `contextSnapshotRef.isBlank()` 时 apply+ack；
  客户端绑定失败/中断/发送失败返回 `ref=runId`（非空）→ 只关 streaming → `pendingRewrites` 残留、
  失败提示缺失。
- **修复**：错误结果（`ok=false`）即使带 ref 也走 `applyRewrite`（失败语义）+ ACK；
  仅"成功但需回读 snapshot"（ok=true 且 ref 非空）保留等待回读。

### C8 — ON_RESUME 恢复与 rewrite 竞态
- **根因**：`orphanRewrites` 在上一个 Main 块计算、下一个 Main 块应用，两块间有协程让出窗口；
  用户窗口内刚发起的 rewrite runId 不在 observed → 被误判孤儿 → 写入失败通知并占
  `appliedRuntimeRunIds` → 真结果到达时被幂等守卫丢弃（改写内容丢失 + 假"重新生成已中断"）。
- **修复**：孤儿应用前校验 `runId == currentRunId` 则跳过（应用时刻最新值，挡住刚发起的 rewrite）。

### C9 — 新 run 接管旧 run 的 GUI 工具不被打断（动作交错）
- **根因**：`startRun` 的 `cancel()` 只置标志+关资源，不打断旧 run 正在执行的 GUI 工具
  （无障碍手势、wait 循环、type_text）；旧 run 当前工具副作用必然执行完，与新 run 的
  observe/tap 可能重叠。
- **修复**：`AgentLocalTools.execute` 入口检查 `closed`（cancel 触发 close 链）——
  取消后旧 run 的**下一个**工具调用被拒绝（`TOOL_INTERRUPTED`，明示不要自动重放），
  截断交错窗口。正在执行中的工具副作用无法中断（平台限制），但不再继续执行后续工具。
