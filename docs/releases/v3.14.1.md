# v3.14.1 — 计划模式只读收口与审批全流程修复

发布日期：2026-10-21
versionCode：2026102102（上一版 2026102101 / v3.14.0）

## 背景

v3.14.0 发布后在真机上做了两轮完整回归（设备全程未清数据，含已配置的模型）。
本轮修复的是回归中暴露的问题，**全部经过真机验证**。

## 修复

### 1. 批准后审批条整程不消失（最严重）

**现象**：点「批准并执行」后，界面仍显示"计划已提交，等待你确认"+ 可点的批准按钮，
一直挂到执行结束。数据库里阶段已是 executing、第一步已标记进行中。

**根因**：`planPhase` 只在会话切换与 run 结束时刷新。而批准后的执行可能持续数分钟，
这段时间 UI 一直停在 REVIEW 阶段——用户会以为批准没有生效。

**修法**：审批条可见性增加 `!isStreaming`；同时 RunStarted / ToolFinished 事件里
节流（1s）刷新阶段。真机验证：点批准后 **2 秒内**审批条消失，状态转「执行中」。

### 2. 取消计划后进度条残留

**现象**：点「取消计划」后，输入区顶部仍显示旧计划的 0/N 进度条与步骤。

**根因**：进度条是从消息流里的清单回执解析的，而回执永远留在历史里；
取消只清了数据库，没抑制这条解析路径。

**修法**：阶段为 NORMAL 时不渲染进度条。真机验证：取消后进度条、chip、审批条全部消失。

### 3. 模型断言"没有能力执行计划"

**现象**：模型提交计划后向用户摊牌"本轮公开给我的工具里没有任何写入能力……
这些我无法执行"，容易让用户以为批准也没用。

**根因**：规划轮次的工具列表确实只含只读工具（这是设计），但**批准后是新一轮运行、
会解锁完整工具**。模型没被告知这一点。

**修法**：提交回执中补充说明"当前轮次只读是计划模式的约束；用户批准后会以完整工具执行，
不要因为本轮工具受限就断言计划无法执行"。

## 改进

### 计划模式只读改为「目录级隐藏」

此前只读约束是运行时拦截：模型仍能看到 `todo_write` 等写工具，真机实测小模型
（sensenova-flash-lite）看到就会选它，被拦截后不改，还要用户提示才知道用 `exit_plan_mode`。

现在只读阶段（PLANNING / REVIEW）的**工具列表本身**就不包含任何写工具，模型想选也选不到；
运行时拦截保留作兜底。并新增单测锁死一条口径：**"模型能看到的"必须等于"运行时允许的"**
（目录里出现的每个工具都不能再被运行时拦截）。

真机效果：不提示 `exit_plan_mode`，模型 33 秒自主完成调研并提交计划，`todo_write` 尝试 0 次。

### 其它

- 工具卡标题补映射：`exit_plan_mode` 此前显示「准备执行」，现为「提交计划」（另补 6 个）
- 审批条删掉与提示重复的页脚文案
