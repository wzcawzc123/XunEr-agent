## Eta v3.6.1

小修复：**OCR 失败可定罪 + 冷启动超时修复**（v3.6.0 真机 OCR 三连 null 的诊断版）。

### 背景（2026-10-04 真机取证，会话「测试ksu」）

v3.6.0 实测 `locate_on_screen` 树匹配工作正常（18 节点确实无目标），但 OCR 通道三连
`OCR 不可用`（LOCATE_MISS）——异常被静默 catch 吞掉，logcat/载荷零痕迹，无法定罪，
模型只能回落目测，再次出现"正上方半个字"偏移。

### 改动

- **诊断链**：`ScreenTextRecognizer.lastFailure`（异常类名+消息）+ 每步失败写
  `ocrDiag`（image=null / decode_failed / init_failed / recognize_failed / screen_dims）
  → 直接进 LOCATE 错误载荷与 logcat（`EtaOcr` tag），下一轮实测自解释；
- **冷启动超时 5s→15s**：首次识别要加载 11MB pipeline so + 模型；
- 已排除的假设（负结果记录）：APK 模型资产完整（mlkit-google-ocr-models + libmlkit
  google_ocr_pipeline.so 都在）；排除 GMS 变体实验=编译失败（`ChineseTextRecognizerOptions`
  仅存在于 play-services-mlkit 变体，bundled 包只带资产）；后台线程执行（非主线程限制）。

### 验证

- 定向 16 例（locate/ScreenLocator/契约）非环境失败 0；全量门禁见 CI。
