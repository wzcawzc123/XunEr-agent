# v3.11.6 — 上下文板块失败路径加固（快照/恢复容错 + 摘要输入预算）

## 背景

上下文压缩链路（触发 → 摘要 → 经济性检查 → 熔断 → 硬裁剪）已在 F3/F8 锁定并覆盖主要场景，
但**失败路径与成本侧仍有缺口**：

- **恢复路径硬失败**：`AgentContextSnapshot.decode` 对损坏数据抛异常（kotlinx 解码 + `require(version==1)`），
  单条 in-flight run 快照损坏（写入中断/版本升级残留）会中断整个 UI 启动恢复（`recoverRuntimeRuns` 无 catch）；
  `AgentRuntimeWire.runResultFromBundle` 的 IPC 解码同源同类。
- **边界不变量硬崩**：`AgentRuntimeHistoryReducer` 对「快照声称覆盖 > transcript 实际长度」（快照先落库、
  transcript 未落库的进程死亡时序）用 `require` 硬失败，使整次结果应用失败。
- **性能冗余**：压缩发生后每轮 loop 都重新发布全量快照并写库，内容未变时成本重复。
- **成本侧缺口（R4）**：摘要请求全量携带待整理历史，无输入上限——真机曾出现单轮 input 75 万 tokens，
  摘要请求本身又贵又可能超 provider 上限（INVARIANTS 已知缺口 R4 记录）。

## 修复

### 逻辑修复（可称根因修复）

1. **快照解码容错**：`AgentContextSnapshot.decode` 内 `runCatching` 包裹，损坏数据返回 null，
   5 个调用方（检查点恢复 / 归档 / IPC / 终态结果 / 恢复协调器）自动按「无快照」退化，
   恢复落到完整历史 + transcript 兜底，不再抛异常。
2. **RunResult IPC 解码容错**：`runResultFromBundle` 对损坏的 `complete_result_json` 回落字段级 fallback。
3. **Reducer 边界收敛**：`AgentRuntimeHistoryReducer` 将「快照覆盖超出 transcript」从 `require` 硬失败
   改为按 `additions.size` 上界收敛（宁可少拼 transcript 也不让整次结果应用失败，journal 完整保留）。
4. **HistoryTool 结构化错误**：`ConversationHistoryTool` 4 处 `require` 改为返回
   `ok=false, code=INVALID_ARGUMENT` 的结构化结果，模型获得具体错误码而非泛化 `TOOL_ERROR`。
5. **快照写库节流**：压缩后每轮发布的快照内容未变化时跳过 `saveContext`（`AgentRuntimeRunExecutor` 单回调内
   去重，崩溃恢复语义不变——每轮仍刷新最新快照）。

### 策略调参

6. **摘要输入预算（R4）**：新增常量
   `summaryInputBudgetChars = min(窗口/2, 512_000)`（下限 32_000，窗口未知按 128k 基准）。
   触发条件：序列化历史超过预算时，从最旧端丢弃消息至预算内（protectedUser 与逐字保留尾部不受影响）；
   `covered` 只计实际进入摘要的用户轮次（跨 run 对账自洽）；摘要消息注明「更早历史超出预算未纳入」。
   归为策略调参——阈值可调，不改变压缩护栏本身。

### 文档/注释同步（不改变行为）

- `AgentHistoryTrimmer` / `AgentContextSession` 注释：明确硬裁剪就地替换 run 内 messages、
  触发线 0.8（替换过期 0.85→0.75 描述）。
- `AGENT_RUNTIME.md`：触发线 85%→80%、补缺节重试与摘要输入预算说明。
- `docs/specs/context-cost-guard.md`：`ABSOLUTE_TRIGGER_CAP=200_000` → 0（共 3 处）、Success Criteria 修正、
  Open Question 更新（R4 落地，R5/R6 另立）。
- `docs/INVARIANTS.md`：已知缺口 #3 标记 R4 已落地。
