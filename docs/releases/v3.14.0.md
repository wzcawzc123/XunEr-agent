# v3.14.0 — 全局审查修复：计划模式入口重构、备份纳入用户资产、测试隔离

## 背景

v3.13.8 之后做了一次覆盖 100 个提交（v3.11.27 → v3.13.8）的全局审查，
按「功能不可达 / 数据丢失 / 约束可绕过 / 一致性」分级，本版修复其中的 P0 与高价值 P1。

审查报告：`docs/reviews/global-review-2026-10-20.md`。

## 计划模式

### 入口重构

输入栏那一排恢复原样（全是同尺寸图标按钮），计划入口移到**加号菜单**：

- 未进入时菜单项为「计划」，已进入为「退出计划」，待批准时显示「计划待批准」并禁用
- 选中后输入区出现 `[📋 计划 ×]`，形态与附件 chip 完全一致；点 × 即退出（不发消息、不起 run）
- 之前那个带文字的 pill 与这排图标高度不齐、还挤占空间（真机反馈），已删除

### 计划正文进对话流

- `exit_plan_mode` 回执改为结构化（`[ETA_PLAN_BEGIN]` / `[ETA_PLAN_END]` 包裹正文）
- UI 拆出正文交给 `StaticMarkdown` 渲染，**与聊天气泡同款**，且不受工具卡 12 行截断
- 审批条不再承载正文，只保留「批准并执行 / 取消计划」与一行提示
- 此前审批条「三行截断 + 点击展开」展开后没有滚动容器，长计划直接被裁掉

### 审批与只读约束

- **批准/取消改为整句精确匹配**。此前是前缀匹配，「执行前先确认备份」会被当成批准
  直接进入 EXECUTING 并开始改设备；「取消按钮的颜色改成红色」会被当成放弃计划
- `navigate` 只接受 http/https（此前可加载 `file:` / `content:` 等协议）
- `androguard_analyze` 的透传参数改为 **token 白名单**（`-o /path` 这类写文件选项整段丢弃）
- REVIEW 阶段不再显示点了没反应的 ×；`showsToggle` 从死代码恢复为真实调用

### 模型建议（不做「模型自行进入」）

新增建议协议：普通阶段模型判断任务复杂时，可在回复最后一行输出 `[[PLAN_SUGGESTION]]` 加理由，
界面在消息末尾渲染「进入计划模式」按钮，**用户点一下才进入**。

计划模式是权限边界切换（只读 ↔ 可写），让模型自行进入等于让它自己改自己的权限——
主流产品（Claude Code / Kimi / Cursor / Codex / Aider）无一例外都由用户主动开启。

## 数据安全

### 备份纳入用户资产（schema v4）

此前 `conversation_todos` / `conversation_plans` / `agent_tasks` **既不在备份里**，
恢复时还会被无条件清空——**导出一次再导入，所有任务清单与计划正文全部消失**，且没有任何提示。

现在：

- `schemaVersion` 3 → 4，三段随备份走
- 恢复按版本门控：v4+ 才清空重建；**旧备份（v1–v3）保留本机数据**（缺数据不等于要删数据）
- 删除会话时同步清理绑定它的自动任务（此前任务会向已删会话持续投递并计费）

### 迁移链单一来源

`DATABASE_MIGRATIONS` 成为生产与测试共用的唯一来源，并新增「迁移链连续」守门：
加了 `SCHEMA_VERSION` 却漏写迁移，测试立刻变红。

此前测试里手抄了一份迁移列表，两边可以不一致而测试全绿；而生产配置是
`fallbackToDestructiveMigration(dropAllTables = true)` —— 漏一个迁移就是全量用户数据丢失。

## 用量统计

- 页面改走 `MiuixScaffold`，标题进 TopAppBar，与其他页同高同字号（此前左对齐、无返回键）
- **「按模型」卡片此前从未显示过**：页面只调 `all()`，而 `all()` 不填 `byModel`。
  现在 `all()` 复用 `byModel()`，并抽出 `AgentCostSummary.fromModels` 纯函数
- 顺带修正统计错误：`fromModels` 原用 `fromRows` 按「模型行数」算轮次，导致总轮次等于模型个数

## 记忆页

- 「整理」前加脏检查与确认弹窗（此前静默覆盖未保存草稿，与「切换目标」的处理自相矛盾）
- 搜索框不再 trim 输入（此前无法输入空格，多词搜索不可用）

## 测试与工程

- 新增跨模块测试：计划回执/建议协议/用量汇总/UI 契约/迁移链/备份恢复
- **修掉记忆单例的测试顺序依赖**：`AgentMemoryRepository.init()` 只绑定首次 Application，
  Robolectric 换测试类后路径僵住，表现为「写入成功但读出来是空的」，只在跑全量时复现
- 新增 `PlatformAssumptions`：把「AtomicFile 的 rename 覆盖在 Windows 不可靠」这类
  平台限制显式标注并跳过，让本地红点重新等于「真正需要人看的问题数」
- 清理死代码：`AutoTaskTrigger` 整类、`AutoTaskDispatcher.clearAll`、`AutoTaskStore.markRan`、
  `AgentMemoryAction.Refresh`、计划 pill 遗留常量与 import

## 验证

- **Linux（CI）全量绿**：lint + 1955 例单测 + debug/release 构建全部通过
- 本地（Windows）：1955 例 / 40 失败 / 30 跳过。40 个失败全部是终端 PTY、Proot、文件权限、
  图片编解码等 **Linux-only 依赖**；记忆与备份相关失败为 0
- 迁移链守门已实测：把版本改成 30 而不加迁移，测试立刻 2 红

## 已知风险（发版时未消除）

- **UI 改动未经真机回归**：计划入口（加号菜单 + chip）、计划正文的 Markdown 呈现、
  用量页骨架、记忆整理确认框，全部只过了单测与构建，**没有在设备上点过**。
  设备整个开发周期处于离线状态。
- **备份格式升级未做端到端验证**：导出 → 清数据 → 导入这条链路只有单测覆盖
  （`exportAndImportRestoresPlanAssetsAndAutoTasks`），建议首次使用前先导出一份留底。
- 自动任务在非 root 设备上仍无 App 内触发源（历史遗留，本次未动），
  根因与修复方案见审查报告第 4 批。

## 升级提示

- **数据库仍为 v29**（本次未改 schema，只加了导出段）
- **备份格式升至 v4**：新备份可导回旧版 App 会因 `schemaVersion` 上界被拒（这是设计）；
  旧备份导入新版会保留本机清单与计划
- 计划模式的文本协议有变：批准/取消不再接受前缀匹配，须为完整词
  （如「批准」「批准并执行」「取消」）；带附加说明的输入会被当作修改意见重新规划
