## Eta v3.8.1

小修复：**终端工具报错可诊断化 + 旧工具名迁移引导**（合并 v3.8.0 后的全量审查产出）。

### 因由

合并上游 3.2.0 后，终端相关失败提示**无法区分「设计限制」与「真实故障」**：
`arguments 必须且只能符合 oneOf 中的一个 Schema` 把「0 个分支匹配」与「匹配数超上限」
折叠成同一句话，且不指出字段 —— action 拼错、多传字段、取值非法这三种完全不同的
原因会得到同一条报错，会话里只能靠猜（本轮实测连续踩中，包括改动后立刻自踩）。

### 修复

- **oneOf / anyOf 分支报错可诊断**（`AgentToolCallValidator.branchFailure`）：
  - 分支数超出上限 → 报出实际匹配数（"同时符合多个互斥分支……已判定 N 个"）；
  - 无分支匹配 → 附各分支首个失败原因（含字段名，最多 3 条）与环境字段形状。
- **已并入其他工具的旧名改报迁移引导**：`run_command` 不再回笼统的"未在能力目录中声明"，
  改为「已并入 terminal：请改用 terminal（action="exec", environment="android"）」。
  该名字已由上游 42b9930 从能力目录移除（执行侧与显示映射仍在），属**永不自愈**的失败。
- **terminal description 补充两条易踩限制**：各 action 的专属字段白名单、`environment=linux` 需 root。

### 审查结论（一处误判已纠正，留痕备查）

审查中一度把 **「能力目录拒绝 / 运行时接受」** 的不对称（`action=open_and_exec`、
`environment=alpine|debian`）判定为"上游漏同步 schema"，并已动手改 schema —— 被
`RootShellTerminalControllerTest`（明确断言 `assertNotNull(schema)` + `assertNull(runtime)`）
与 `AgentToolCatalogTest`（断言 enum 恰为 android/linux）拦下后**全部回滚**。

确认该不对称是**有意分层**：能力目录只暴露规范写法以引导模型，运行时保留旧名容错
（`RootShellTerminalControllerTest` 内另有 4 处直接以 `open_and_exec` 调用 controller）。
新增 `TerminalToolContractTest` 把这一分层显式锁住，防止将来被"顺手统一"掉。

### 验证

- 新增与改写的单测全绿：`AgentToolCallValidatorTest`（+3）、`TerminalToolContractTest`（5 例新建）；
- 全量测试：非环境失败 0（含两处曾被我改动触发的既有测试，已随回滚复原）；
- `RootShellTerminalControllerTest` / `AgentToolCatalogTest` 定向回归通过。
