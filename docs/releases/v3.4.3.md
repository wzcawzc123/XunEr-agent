## Eta v3.4.3

本版一次做完三件事：**把"模型反复重读记忆"查到根**、修掉真正的病根、并撤回一处在 3.4.2 开发中引入
但经核查站不住的隐私豁免。同时首次完整带上长期记忆系统的按章节读写能力。

### 一、先说结论：那 30 次重复不是"忘了"

设备数据库里 `我的记忆` 会话的实测记录（会话共 223 条消息，`memory_get` 45 次）：

- **连续 30 次**调用（sort 40→99）的参数**全是"读取记忆"**——不带任何参数；
  结果**全是"已读取记忆 · 398 行 · 106706 字节"**，一字不差。
- user 消息的位置是 idx = 0, 9, 14, 29, 38, **80**, 107 …，因此连续性最强的 **20 次
  （sort 40→78）全部落在同一次任务内**。而在同一次任务内，发给模型的上下文用的是原始消息
  （`AgentLoop` 直接投影 `messages`），**脱敏根本不参与**——模型看得见，仍然重复了 20 次。

模型的推理写得很直白：

> The query "hook APK" matched but **the returned window shows lines 1-63? Odd** …
> **The query result seems to have returned the first page anyway.**

真正的病根：**`memory_get` 只回一个 `has_more=true`，却不告诉模型"下一段从哪读"**。
模型想要完整的 398 行，于是拿同样的参数一遍遍重试，每次都只拿到第 1 页。

### ① `memory_get` 结果附带分页续读指引

分页读取（未指定 `section` / `query`）且仍有后续内容时，结果额外给出：

```json
{
  "has_more": true,
  "end_line": 63,
  "next_start_line": 64,
  "paging_hint": "已返回第 1-63 行（共 398 行）；还有内容未返回，继续读取请传 start_line=64"
}
```

- 读到**末页时不再出现**这两个字段，避免模型以为还有内容而空转。
- **检索路径（`query`）不套用**该提示——那里的 `has_more` 是"还有匹配未显示"，语义不同。

### ② 撤回「记忆结果正文可见」

3.4.2 开发过程中曾把 `memory_get` / `memory_write` 的**结果正文**从持久 transcript 的脱敏中豁免，
理由是"模型看不到自己读过的内容就会反复重读"。上面这次核查证明**这个理由不成立**：

- 重复发生在**同一次任务内**，而那一层本来就不脱敏；
- 同一批证据里被一起引用的"另一会话 **1,283 次 `terminal`**"同样不成立 —— `terminal`
  **从来不在敏感名单里**，它的结果一直是明文进入历史的。

而豁免的代价是实打实的：`AgentConversationCodec.transcript()` 同时用于重建模型上下文与持久化，
`AGENT_RUNTIME.md` 写明"待确认结果和外部入口归档会把完整脱敏 transcript 一并写入 Room"，
豁免会让**记忆正文写进会话数据库，且不可逆**。

因此本版撤回该豁免，恢复"记忆工具的参数与结果在持久 transcript 中**整体脱敏**"，同时保留
3.4.1 引入的**形状**（只保留键名与各值的类型/长度，取值一律不留）。`AGENT_RUNTIME.md` 同步改回。

> **更正**：`docs/releases/v3.4.1.md`（已发布，保留原文）与若干代码注释里把
> "34 次 `memory_get`、1,283 次 `terminal`"当作"脱敏致失忆"的证据，该归因**不成立**。
> 真正成立的只有一条：脱敏会让模型在**下一次任务**里看不到上一次读过的内容。

### ③ 长期记忆系统：按章节读写（首次随版本发布）

- **按标题读写**：`memory_get(section=…)`、`memory_write(mode="replace_section", section=…)`。
  标题匹配忽略 `#` 前缀与大小写；未匹配或多义时返回可用标题清单/候选行号，而不是空结果。
  替换一级章节要求 content 保留一级标题。
  —— 这是**根因修复**：此前提示词要求模型"优先替换已有章节并去重"，但 `memory_write`
  只能用行号定位，模型想替换却没有可靠手段，只能 append，这才是用户文件里出现**重复
  `# 核心记忆`** 的成因。
- **核心段合并注入**：存在多个同名 `# 核心记忆` 时**全部合并**注入（原先只取第一段，
  导致第二段 69 行 / 12,408 字符整段掉出自动注入）。
- **append 护栏**：追加内容若含已存在的一级标题会拒绝（`MEMORY_DUPLICATE_HEADING`），阻断重复段再生。
- **注入按整行边界截断**，并报告"共 N 行、已注入前 M 行、可从第 K 行继续"，不再把最后一行切在句中。
- **检索上下文改为优先展开整个小节**（≤24 行的小节整节返回，大节取窗口），原先固定 ±1 行。
- **`changed` 回显**：写入后逐字节相同会回 `changed=false`，不再让"什么都没发生"也报成功。
- **清空需确认**：`clear` 要求 `content="DELETE_ALL"`。
- **`safeTake`**：分页/区间截断不再切断 UTF-8 代理对（emoji）。
- 新增 11 项针对性测试。
