# v3.13.6 — 记忆编辑「放弃」后保存栏残留修复

## 背景

真机反馈：编辑记忆时浮出的保存栏（保存/放弃），点「放弃」后**保存栏仍在**。

## 根因

v3.13.3 起保存栏可见性由显式 `dirty` 标记驱动（替代逐帧 `draft != savedContent`
全量比较）。「放弃」按钮当时复用了击键路径 `DraftChanged(savedContent)`：
`updateMemoryDraft()` **永远置 `dirty = true`**、从不比较 —— 于是放弃后
`draft` 虽已重置回保存内容，`dirty` 仍是 true，保存栏按可见条件
（`dirty || isSaving`）继续显示。注释里提到的 `resetDraft()` 实际并不存在，
放弃路径从未真正实现「丢弃并清脏」的语义。

## 修复

- 新增 `AgentMemoryAction.DiscardDraft`（独立语义，不复用永远置脏的 DraftChanged）。
- `AgentMemoryStore.resetDraft()`：`draft = savedContent`、`dirty = false`、
  顺带按低频操作惯例重算一次精确 `draftBytes`（对齐 saveMemory/clearMemory 的做法）。
- 保存栏 `onDiscard` 改绑 `DiscardDraft`；dispatch 接住新 action。
- 确认无其他「放弃」路径复用 `DraftChanged(savedContent)`。

## 验证

- 编译通过；全量门禁 365 失败全部为环境性（363 Robolectric aarch64 + 2 DexKit 基线），
  新增非环境失败 = 0。
- 真机路径：编辑记忆 → 浮出保存栏 → 点「放弃」→ 保存栏应随 dirty 清零消失。
