# v3.13.8 — 计划模式闭环：只读规划 → 审批 → 执行 + 用量统计重排

## 背景

v3.13.7 之前，项目里只有「任务清单」（`todo_write` + 进度条），
缺的是「计划」这个交互姿态：没有只读调研阶段、没有用户批准环节，
模型可以边做边改清单，进度条也会在失败回执下整块消失。

这一版把它补成对标 Codex Plan / Kimi EnterPlanMode-ExitPlanMode / DSH plan-mode 的完整闭环。

## 计划模式

### 1. 状态机与审批闭环

```
NORMAL ──点「计划」或 /plan──▶ PLANNING ──exit_plan_mode──▶ REVIEW
REVIEW ──「批准」──▶ EXECUTING ──步骤全部结束──▶ NORMAL（自动收尾）
REVIEW ──「取消」──▶ NORMAL
REVIEW ──其他内容──▶ PLANNING（按修改意见重做）
```

- 新增 `conversation_plans` 表（DB v29，迁移测试覆盖 v6 → v29 全链）：
  阶段、`plan_id`、`version`、`approved_version`、计划正文、时间戳。
- **批准版本绑定**：只有 `approved_version == version` 才允许按已批准计划执行；
  任何一次重新提交都会让旧批准失效。
- **自动收尾**：执行阶段所有步骤进入终态后自动回到普通对话，下一轮不再背着执行提示。

### 2. 入口不再是斜杠命令

- 输入栏新增「计划」pill：普通对话点一下进入规划；规划/执行中点一下退出。
- 计划提交后，输入框上方常驻审批条：**批准并执行 / 取消计划**，并直接展示计划正文
  （默认三行，点击展开），不必再翻工具卡。
- 规划阶段输入框占位文案改为「描述任务，我先只读调研，再给你方案」。
- `/plan`、`批准`、`取消` 等文本协议保留：语音、外接助手等无 UI 入口仍可用，
  两条路径共用同一套校验。

### 3. 只读硬约束

`PLANNING` / `REVIEW` 阶段由 `AgentPlanModePolicy` 白名单拦截修改类工具
（写文件、终端、点击输入、`memory_write`、`create_auto_task`、MCP 写工具等），
不只依赖提示词；`browser_use` 按 action 放行读取类操作。
新增的写工具默认被拦截——漏配的代价是"计划阶段不能用"，而不是"计划阶段改了设备"。

### 4. 执行期改计划必须重新批准

`EXECUTING` 下新增/删除/改写步骤会被判定为**超出已批准范围**：
清单照常落库，但版本 +1、`approved_version` 归零、退回待批准，用户重新确认后才能继续。
只推进状态（pending → in_progress → completed）不算范围变更，否则每完成一步都要重新批准。

范围比较按 **subject 多重集**而非 id：模型不提供 id 时生成的是 `step-{index}` 位置 ID，
删掉中间一条会让后续 id 全部平移，按 id 比较会把"删 1 条"误报成"整段重写"。

### 5. 计划正文进入上下文

此前计划正文只存在于 `exit_plan_mode` 的当次回执里，上下文压缩后模型只剩步骤清单，
会忘掉目标、约束和验收标准。现在按阶段注入：

| 阶段 | 注入 |
|---|---|
| REVIEW / EXECUTING | 计划正文 + 完整清单 |
| NORMAL | 仅当清单还有未完成项时，只注入清单 |
| PLANNING | 不注入 |

### 6. 顺手修的问题

- **失败回执被判成功**：`todo_write` 校验失败返回纯文本，`isSuccessResult` 兜底成 true，
  一次参数错误会让整张进度条消失。现在按工具名识别失败前缀。
- **非法 status 静默降级**：写 `done` 会被当成 pending，现在整批拒绝并列出可用值。
- **取消项制造 100% 假完成**：取消项移出分母后显示 `2/2 完成`；现在单独计数、终态明确提示。
- **孤儿行**：删会话 / 恢复备份会一并清理 `conversation_todos` / `conversation_plans`。
- **无会话标识的入口挂载计划工具**：不再挂载，模型认真调一次只会拿到"无法保存"。
- **计划结束后仍每轮注入旧计划**：原注入条件是"非 PLANNING"，NORMAL 也满足，
  计划完成后每轮闲聊都会白背最多 3200 字旧计划（token 泄漏）。已按上表收紧。
- 自动任务（后台定时任务）不挂计划工具、不注入清单、不参与阶段路由，避免改写用户计划。
- 角色扮演会话同样不挂载计划工具、隐藏入口。

## 用量统计重排

原布局三张卡各带一份标题与长解释，六个数字撑满一屏、信息密度低。

- 改为「结论卡 + 明细卡」：**实际计费输入**放大为主数字，缓存命中率与"为什么"作为它的解释，
  用户不必再自己拿两个数相减。
- 明细补入「其中缓存命中」原始数值——此前只有百分比，看不到基数。
- 按模型分组保留。

## 验证

- 计划模式相关测试 **133 例全绿**（状态机、只读策略、审批路由、范围漂移、
  注入边界、迁移 v6→v29、工具目录、UI 图标）。
- 全量单测 1919 例；47 个失败全部是项目既有的 Windows 平台差异
  （终端/PTY、路径语义、记忆文件锁、符号链接），与改动前一致，计划/用量/提示词相关 **0 失败**。
- `assembleDebug` / `assembleRelease` 均通过；release 包 R8 生效。
- 未做真机回归（计划模式 UI 入口与审批条为新增界面元素，待装机验证）。

## 升级提示

- **数据库升至 v29**：新增 `conversation_plans` 表。回滚到旧版本 APK 时，
  Room 会因库版本更高而拒绝打开，需先卸载或清数据。
- 测试侧修正 `AgentMemoryGetPagingTest` 的顺序依赖（原填充量恰好等于默认分页大小）。
