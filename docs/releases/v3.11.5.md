# v3.11.5 — 纯文本模型出站统一剥离图片块（恢复被 merge 丢失的 supportsVision 门控）

## 背景

`supportsVision=false`（纯文本模型）时，图片剥离只在 `AgentModelClient.complete()` 初始构建后执行一次，
**工具回合内新增的图片观察消息不经过剥离**，会原样发往不支持图片输入的模型（400 或静默丢失视觉内容）。

排查发现这是**回归**：`3257285`（feat(vision)）引入时 `AgentLoop` 本有 `if (config.supportsVision)` 门控
（工具截图不进会话），被 merge `2757308`（合并上游 3.0.6）冲突解决时**静默覆盖丢失**。
`browserUse()` 是工具层唯一漏网产图源——它只检查 `browserToolsEnabled()`，不检查 `supportsVision()`，
而 `AgentBrowserSession.screenshot()` 默认 `read_image=true`。

## 修复

1. **出站层统一剥离**：`stripImagesForTextOnlyModel` 改为返回副本、不再原地改写持久 messages；
   剥离点移到 `AgentLoop` 每轮出站前（`pruneRequestMessages` 之后、预算估算之前），
   初始附件与循环中工具截图全覆盖，且预算口径自动与真实请求一致。
2. **浏览器工具补防护**：`browserUse()` 在 `supportsVision=false` 时静默降级 `read_image=false`，
   对齐 `observeScreen` 行为，堵住浏览器截图漏网产图路径。
3. **统一图片判定**：新增 `isImageBlock` 谓词，剥离 / 预算 / 脱敏三处复用，消除判定漂移。
4. **占位符收敛**：纯图片消息才补「图片已忽略」提示，有文本的消息只删图片块，历史不再堆积重复提示。

## 验证

- 新增 7 个用例：三种格式（Chat `image_url` / Responses `input_image` / Anthropic `image`+`source`）
  剥离单测、返回副本且原数组不变、无可剥时返回原引用、`isImageBlock` 全覆盖；
  纯文本模型 + 工具返回图片 → 每轮出站请求零图片块（集成测试）。
- 全量 **1641** 用例，失败 **356** = 354 环境性（aarch64 Robolectric）+ 2 既有（root 下 `canWrite`），
  **与改动前基线逐项一致**（stash 基线复跑对照）。
