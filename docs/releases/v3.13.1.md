# v3.13.1 — 记忆页与用量页的布局修复

三个界面问题，全部属于「代码逻辑正确、但布局或线程约束写错」，CI 与单测都拦不住，
真机点开才暴露。

## 修复

### ① 长期/短期记忆切换按钮被设置卡片压住

`AnimatedVisibility` 内部用 `Layout` 实现，多个子元素会被测量后**放在同一位置**
（不是纵向排列）。切换按钮与「启用记忆」设置组因此重叠，后者盖住了前者。

修复：`AnimatedVisibility` 内部包一层 `Column`。

### ② 会话活跃度热力图少两行、与图例挤在一起

`Canvas` 高度写死 `88.dp`，而格子尺寸由宽度决定（`cell = width / (weeks × 1.6)`），
7 天纵向实际需要约 118dp → 后两行被裁，图例紧贴下方造成「重叠」观感。

修复：改用 `aspectRatio(weeks × 1.6 / (7 × 1.35))`，高度随宽度自适应。

### ③ 用量统计页永远是空的，且透出设置列表

- `LaunchedEffect(Unit)` 默认跑在**主线程**，而 `AgentCostRepository.all()`
  是同步 Room 查询 → 抛 `IllegalStateException` → 被 `runCatching` 吞掉 →
  返回 EMPTY → 永远命中「还没有用量记录」分支。
  实际数据为 1789 条记录 / 输入 6.9 亿 tokens / 输出 205 万（手跑 SQL 证实）。
  修复：包 `withContext(Dispatchers.IO)`。
- 页面 `Column` 没有底色，透出下层设置页。修复：加 `background(surface)`。

## 备注

「主线程访问 Room」在本轮出现两次（另一次是 `AutoTaskService.onStartCommand`，
已在 v3.13.0 修复）。已筛查 `ui/` 下其余 `EtaDatabase.get` 调用，
`AgentConversationStore` 的两处均在 IO 上下文内，无同类残留。
