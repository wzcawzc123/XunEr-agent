# v3.11.0 — 工具结果修剪器

功能迭代：新增**确定性的工具结果修剪**，在零模型调用的前提下给上下文瘦身。

## 为什么做

实测（会话「性能调度模块-新会话」，431 轮）：

| 事实 | 数值 |
|---|---|
| 工具结果占消息内容 | **91.8%** |
| 工具结果 878 条，中位长度 | **556 字符** |
| p90 / 最大 | 1,593 / 16,846 |

工具结果是上下文里最大的一块，且多数在后续轮次不再被引用。

## 做法（参照 deepseek-harness，MIT）

上游 `compaction-tool-result-pruner` 的核心：**确定性、无模型调用**的头/尾保留修剪 ——
只保留头部与尾部，中间替换成固定标记；已修剪内容必然落在预算内，因此**幂等**，重复执行不再变化。

本机两处适配：

1. **参数重定**：上游默认 `8192/4096/1024` 面向 coding agent 的 bash 巨型输出；本机实测 8192
   只命中 7/878 条、省 6.5%，几乎无效。改为 **2048/1024/256** 后命中 57 条、省 **26.3%**。
2. **JSON 安全**：上游只处理纯文本；本机多数工具返回 JSON，按字符切会破坏结构。改为先尝试
   JSON 解析，成功则递归修剪超预算的字符串叶子（结果仍可解析），非 JSON 才走纯文本。

## 影响面

- 只作用于**发给模型的请求副本**：数据库与界面显示的都是原文，会话持久历史不受影响。
- 不修改任何上游接口、不改变工具执行路径。
- 幂等 ⇒ 每轮修剪出的前缀一致，**不牺牲缓存命中**。

## 验证

- 新增 11 个用例：预算内不动、头尾保留、标记插入、JSON 可解析、嵌套结构、幂等、
  代理对不切裂、空/畸形内容、顶层数组。
- 全量 1623 用例，失败构成为 353 环境性（aarch64 Robolectric）+ 2 既有 root `canWrite`，
  与改动前基线**逐项一致**；CI（x86_64）**全绿**。

## 尚未包含

上游编排的第二步「修剪后重新测量，若已低于阈值则跳过整次摘要压缩」未在本版实现，
留待真机观察修剪效果后评估。
