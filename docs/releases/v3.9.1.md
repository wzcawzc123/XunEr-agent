# v3.9.1 — 摘要长度纪律 + 多代检查点（并修掉一处静默缺陷）

小修复：把 v3.9.0 引入的两处风险堵掉，并修掉一个被新用例抓出来的键名错误。

## 修复

**① JSON 键名错误（真 bug，v3.9.0 引入）**
`AgentContextCompactor` 读取检查点标记时用的是 `contextSummary`，而编解码真源
（`AgentConversationCodec`）实际写的是 **`_eta_context_summary`**。后果有两层：

- 多代检查点逻辑完全不生效（旧检查点会被当普通历史一起压掉）；
- **锚点在第二次压缩后会退回"当前历史里最早的用户消息"** —— 也就是 v3.9.0 想防的漂移本身。

已修正，并新增用例 `previousCheckpointIsKeptInsteadOfBeingRewritten` 锁住行为
（旧检查点原样保留 + 新检查点生成 + 锚点逐字在场）。

**② 摘要长度上限**：12,000 → **16,000 字符**，模板中明确要求
「紧凑要点、不要散文段落、每节尽量不超过 8 条」。
原上限是按自由文本定的；换成 8 小节结构后很容易撞线，而撞线会判 `CONTEXT_SUMMARY_INVALID`
→ 压缩熔断 → 80% 档下「压缩失效但仍按高占用计费」，是最坏的组合。

**③ 多代检查点**：压缩时最近一代检查点**原样保留、不参与重写**，只有更早的检查点才合并进新摘要 ——
避免「摘要的摘要」每轮重写上一代而累积漂移。

## 测试

- `AgentContextCostGuardTest` **7 例**（新增 `previousCheckpointIsKeptInsteadOfBeingRewritten`）
- `AgentContextCompactionTest` 17 例、`AgentContextRecoveryTest` 14 例
- 全绿；本机 aarch64 上 Robolectric 仍为环境性失败（20 例，与基线一致），以 CI 为准。
