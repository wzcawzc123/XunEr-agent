# v3.11.14 — 内存基线治根：启动只载选中会话（其余懒加载）

## 背景

真机实测报告（2026-10-11）问题 3：启动时 `loadSnapshot` **遍历全部会话、逐条全量载入消息**
（本机数据 16 会话 / 24,099 条 / 1,861 万字符）常驻为 UI 状态，
空会话态 Java Heap 即达 123~175MB、长会话态 340MB。
这是问题 1（后台服务被系统回收）、问题 2（编辑重发上下文超限）的**上游内存因素**：
内存基线越高，进程越早触顶，中断与超限越容易被触发。

前序版本已修复中断语义与容量守卫（v3.11.9~v3.11.13），本版治根内存基线。

## 修复

### 逻辑修复（懒加载）

1. **启动只载选中会话**（`AgentConversationStore.loadSnapshot`）：
   仅选中会话全量载入消息 + checkpoint（history/journal）解码；
   **其余会话只载 metadata/title/updatedAt**，messages 置空并带 `messagesLoaded=false` 标记，
   history/journal 也不解码（省去 16 会话的转录解码内存）。
2. **选中/恢复时懒加载**（`AgentConversationStore.loadConversation` + `AgentAppState.selectConversation`）：
   点击未载入会话先轻量占位显示，异步补载全量后再刷新；快速连续切换会取消旧加载任务（防竞态）。
3. **保存防误删**（`AgentConversationPersistence`）：未载入会话的保存**保留 metadata 但跳过消息差分**
   （不 deleteMessagesFrom / 不 insertMessages）——messages 为空占位若参与 diff 会把库中历史整段误删。
4. **跨会话入口强制先载入**（恢复 / 续跑 / 外部导入 / 孤儿重写 / 导出 Markdown）：
   这些路径直接读写会话 messages，若目标会话未载入会用空消息覆盖丢历史或跳过恢复丢中断进度；
   现统一先懒加载该会话再操作，语义与懒加载前一致，**无回归**。
5. **列表预览回退**（`Snapshot.previews`）：未载入会话的最后一条消息在载入时按 1 条小查询缓存，
   会话列表不再显示"暂无消息"。

### 已知降级（可接受并记录）

- **内容搜索范围 = 已打开过的会话**：未载入会话不参与全文内容匹配（搜索即懒加载语义，标题/预览仍可搜）。
- 未载入会话的 roleplay 消息不执行 decorate 修饰（纯展示层，不影响数据与保存）。

## 验证

- 新增单测：懒加载只载选中 / 未载入会话保存不删消息且 metadata 落库 / loadConversation 完整恢复。
- 编译 + 全量回归：新增非环境失败 = 0（Robolectric 由 CI x86_64 全量验证）。
