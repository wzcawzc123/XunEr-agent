## Eta v3.8.2

小修复：**终端报错诊断再升级**——v3.8.1 发布后经真机实测，诊断仍有 4 个缺口。

### 因由（真机实测证据，非代码推断）

v3.8.1 上线后在设备上直接试了两个真实错误场景：

1. `terminal` 传 `action=open_and_exec`
   → 报「不符合任何分支……分支1：arguments 符合了 not 禁止的 Schema；分支2：arguments.action 不在允许值集合中；分支3：…」
2. `daemon_logs` 多传 `environment`
   → 报「……分支1/2/3：arguments 符合了 not 禁止的 Schema」（三条一模一样）

暴露的问题：**分支只报编号不报 action 名**、**`not` 不说是哪个字段多余**、
**只列前 3 条看不到全集**、**从不告诉模型合法取值有哪些**。模型拿到这种报错仍无法自愈。

### 修复（全部位于 AgentToolCallValidator，只改文案不改判定行为）

- **分支带标签**：`action=exec：…` 取代 `分支2：…`（从分支的单一枚举字段推导）；
- **`not` 报出违规字段**：`arguments 含当前 action 不接受的字段：environment（请移除后重试）`；
- **附合法取值全集**：`；「action」的合法取值：open、exec、read_async_result、close、daemon_start、daemon_list、daemon_logs、daemon_stop`；
- **截断显式说明**：`（共 8 个分支，仅列前 3 个）`。

无法归因的形态（无 properties 的分支、无 `required` 的 `not`）一律回退原文案，不做猜测——
`fetch_url` 的 `oneOf`（纯 `required` 分支）已验证仍得到清晰的"分支 N：缺少必填字段 url"。

### 验证

- 新增单测 2 例（复刻 terminal 的 oneOf + 专属字段白名单真机场景），
  `AgentToolCallValidatorTest` 累计 11 例全绿；
- 全量 1581 例：新增非环境失败 0（仅 2 个 DexKit 存量）；
- CI 复验通过后发布。
