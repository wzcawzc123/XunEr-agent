## Eta v3.6.3

小修复：**取证自愈重写为抗混淆版**（v3.6.2 取证代码自己先崩的修正）。

### 双模型对照结论（2026-10-04，mimo / deepseek 各跑一次干净会话）

- **两个模型都主动调用了 `locate_on_screen`** —— 新会话无历史污染时引导层有效，
  此前「测试ksu」不调 locate 是会话内 5 次失败历史的理性规避；
- 两个模型失败签名完全一致：`getClient:NullPointerException` —— OCR 病灶与模型无关；
- **v3.6.2 取证自身崩溃**：`forensicsErr=NoSuchElementException` —— 反射按类名字符串查字段，
  而 R8 在 release 下改名且逐构建变化（mapping 实锤 `ComponentRuntime→fv0`、
  `MlKitContext→qz2`），自愈根本没执行。

### 改动（rename-agnostic 重写）

- 全部反射改用**编译期类字面量**（`MlKitContext::class.java`，R8 同步改名）与
  **签名匹配**（静态双参 `(Context, List)` 方法定位），零类名字符串依赖；
- 字符串仅保留 manifest 指定组件（service 名、meta-data registrar 名——
  consumer keep `-keep class * implements ComponentRegistrar` 保名）；
- 逐步打点：`holder/ctx/rt/registrars/每registrar组件数/reinit` 任一步失败带标签进载荷；
- 自愈流程不变：读状态 → manifest 手动发现 → 逐个实例化 → 清静态 →
  按签名匹配的 `initializeIfNeeded(Context, List)` 重建 → 重试 getClient。

### 验收判据（装机后新会话跑 KSU 场景）

- 好：OCR 直接命中（`source=ocr`）；
- 中：载荷带回完整标签链（`registrars=3 | Text=2 | reinit=ok` 之类），自愈生效或精准定位断点；
- 无论哪种，这次**不会再有哑弹**。
