# v3.11.7 — 手动压缩对齐 deepseek-harness（无需压缩语义 + 压缩计量展示）

## 背景

手动压缩（OP_COMPACT）与自动压缩共享同一压缩引擎（范围选择 / 摘要 / 经济性 / R4 预算，见 v3.11.6 冲突面），
但**失败语义与反馈**有两个缺口，对照 deepseek-harness 的 `command-compact` / `compactNow` 设计：

- **「无可压缩内容」被当失败**：`CONTEXT_NOT_COMPACTABLE`（无安全切点 / 无可压缩历史）走错误路径，
  用户看到「压缩失败」；harness 的 `/compact` 语义是**成功**返回 `null` → "No compactable history yet"。
- **成功无压缩量反馈**：通知只有「上下文压缩完成」；harness 回报
  "Compacted N history items (~M tokens)"（`shadowedSeqs` + `shadowedTokenCount`）。

## 修复

### 逻辑修复

1. **手动压缩「无可压缩内容」→ 成功**（`AgentModelClient.complete` compactOnly 分支，~7 行）：
   捕获 `CONTEXT_NOT_COMPACTABLE` → 返回成功且无快照；正常压缩成功必有快照，
   UI 据此区分「上下文压缩完成」与「上下文无需压缩」。**自动路径行为不变**（自动侧
   `CONTEXT_NOT_COMPACTABLE` 仍走熔断 + 硬裁剪兜底）。
2. **压缩计量展示（R5 前哨）**：新增 `AgentCompactionDetail`（实时路径 `AgentAppState`
   与恢复路径 `AgentPendingResultRecovery` 共用），成功通知展示
   「已压缩 N 条历史、覆盖 M 轮」——N = 压缩前后消息条数差（对应 harness 的 shadowed 语义），
   M = 快照 `coveredUserTurns`。数据全部来自会话/快照现有字段，未引入 token 计量。

### 明确不做

- runtime 层 idle 锁、summary-error 恢复瀑布、持久锁事务：与 fork「独立 run + 幂等 reducer」
  架构不符，收益/成本比低（详见审查结论 M3/M4）。

## 验证

- 新增 **5 个** @Test 用例：
  `manualCompactionWithNothingToCompactReturnsSuccessWithoutSnapshot`（T-M1：无可压缩历史 →
  成功、无快照、不发起摘要请求）+ `AgentCompactionDetailTest` 4 例（T-M2：shadowed 条数 /
  覆盖轮次 / 无需压缩 / 失败回退 / 条数非负）。
- 受影响测试类全绿：`AgentContextCompactionTest`、`AgentCompactionDetailTest`、
  `AgentPendingResultRecoveryTest`、`AgentRuntimeHistoryReducerTest`、`AgentModelClientLoopTest`。
- 全量 **1657** 用例，失败 **357** = 355 环境性（aarch64 Robolectric / DexKit）+ 2 既有（root 下 `canWrite`）；
  **新增非环境失败 = 0**。
