## Eta v3.6.4

根因修复（收官）：**registrar 无参构造被 R8 裁剪 → ML Kit 注册表静默为空**。

### 最终定罪（v3.6.3 取证载荷，标签链一步不哑）

```
ctx=true, rt=true            状态与抗混淆定位全部成功
registrars=3                 manifest 发现 3 个 registrar 全找到
|CommonComponentRegistrar:FAIL NoSuchMethodException   ← 全部死在实例化
|TextRegistrar:FAIL NoSuchMethodException
|VisionCommonRegistrar:FAIL NoSuchMethodException
reinit=skip                  自愈因零实例跳过 → retry 依旧 NPE
```

- AAR 源码核实：`public TextRegistrar()` 明明存在；JVM 构造器恒为 `<init>` 不可改名
  → NoSuchMethod **只能是被裁掉**；
- 链路闭合：Google 自带规则 `-keep class * implements ComponentRegistrar` **只保类名不保
  成员**，而 registrar 只被反射实例化（静态不可达）→ R8 裁 `<init>` → **启动期
  ComponentDiscovery 同样在实例化步静默失败 → 注册表零组件 → `MlKitContext.get(zzo)
  ==null` → `TextRecognition.getClient` NPE**。启动不崩、无日志、双模型（mimo/deepseek）
  同签名，全部对上。

### 改动

- `app/proguard-rules.pro` 增加
  `-keep class * implements com.google.firebase.components.ComponentRegistrar { <init>(); }`
  —— 一行根因修复；
- 取证自愈（v3.6.3 抗混淆版）原样保留：修复万一不彻底时仍带回标签链。
