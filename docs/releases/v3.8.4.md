## Eta v3.8.4

小修复：**真机全量实测驱动**——12 个场景跑下来发现 2 处报错质量问题，一并修掉。

### 真机实测范围（v3.8.3 装机后）

| 类别 | 场景 | 结果 |
|---|---|---|
| terminal 缺必填 | `exec` 无 command | 相关分支排第一 ✓（v3.8.3 新行为） |
| terminal 值非法 | `open_and_exec`、`foobar` | 给出合法取值全集 ✓，但仍在罗列无关分支 → **本版修** |
| terminal 字段多余 | `daemon_stop` + environment | 报出违规字段名 ✓ |
| terminal 嵌套 | `close` 无 session_id/job_id | 内层分支原因也带标签 ✓ |
| terminal 类型错 | `timeout_ms="abc"` | `类型应为 integer` ✓ |
| terminal 越界 | `timeout_ms=999999` | `不能大于 180000` ✓ |
| 环境限制 | `identity=user` + Linux | `LINUX_ENVIRONMENT_REQUIRES_ROOT` 文案清晰 ✓ |
| 坐标 | `locate_on_screen` 查不到 | `LOCATE_MISS` 说明范围+下一步+禁止猜坐标 ✓ |
| 文件工具 | `read_file` 空 path | 报成"目标不是普通文件"，看不出是路径为空 → **本版修** |
| 其他工具 | web_search / skills_read / browser_use 缺参 | 文案精准 ✓ |
| 成功路径 | 正常 `exec` | 功能正常 ✓ |
| 敏感机制 | 脱敏占位回放 | `REDACTED_ARGUMENTS_REPLAYED` 正常拦截 ✓ |

### 修复

1. **action 值非法时直接点明**（`AgentToolCallValidator`）：
   请求的 `action` 若不在任何分支的合法取值内，改为
   `arguments 的 action 值「foobar」不被接受；合法取值：open、exec、…、daemon_stop`，
   不再罗列一堆无关分支的失败原因（真机实测：那些解释只会让人去比对取值表）。
2. **空路径在能力目录层即被拦**（`AgentFileToolCatalog`）：
   `path` 此前只声明 `maxLength`、缺 `minLength`，空串被放行到执行层，
   报成 `NOT_REGULAR_FILE：目标不是普通文件`。补 `minLength: 1` 后
   在 schema 层即报"长度不能少于 1"。
