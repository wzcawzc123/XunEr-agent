## Eta v3.8.3

小修复：**报错诊断第三轮——与请求 action 匹配的分支原因优先展示**（真机实测发现）。

### 因由（v3.8.2 装机后真机逐场景实测）

诊断已可用（分支带 `action=` 标签、报出违规字段、附合法取值全集）。但实测发现一处可用性缺口：

传**合法**的 `action=exec` 但缺 `command` 时，报错把 exec 分支的原因排在**第二位**：

```
arguments 不符合任何分支（要求至少 1 个）；各分支失败原因：
  action=open：arguments.action 不在允许值集合中；
  action=exec：arguments 缺少必填字段 command；已收到字段：action(str:4)、cwd(str:10)、environment(str:5)、identity(str:4)；
  action=read_async_result：arguments 含当前 action 不接受的字段：identity、environment、cwd（请移除后重试）
（共 8 个分支，仅列前 3 个）；「action」的合法取值：open、exec、read_async_result、close、daemon_start、daemon_list、daemon_logs、daemon_stop
```

terminal 有 8 个分支、只列前 3 条 —— 一旦相关分支被挤出去，模型就只剩**无关分支**的解释。

### 修复

- 请求里显式给出的 `action`，其同名分支的失败原因**永远排第一**（即使因此超出条数上限也优先展示）；
- 截断提示按实际列出条数计算。

### 验证

- 新增单测 1 例（锁"与请求 action 同名的分支必须排第一"），`AgentToolCallValidatorTest` 累计 12 例；
- 全量测试：新增非环境失败 0；
- CI 复验通过后发布。

### 真机实测记录（v3.8.2 装机后，本轮审查依据）

| 场景 | 报错质量 |
|---|---|
| `action=open_and_exec` | 分支带 `action=` 标签 + 合法取值全集 + 截断说明 ✓ |
| `daemon_logs` + 多传 `environment` | 明确报出违规字段 `task_id、environment` ✓ |
| `exec` 缺 `command` | 报"缺少必填字段 command + 已收到字段形状"（排序靠后，本版修复）|
| `identity=user` + Linux 环境 | `LINUX_ENVIRONMENT_REQUIRES_ROOT` 文案清晰，属限制类 ✓（description 已说明）|
| `locate_on_screen` 查不到文本 | `LOCATE_MISS` 说明检索范围 + 可行动下一步 + 禁止凭空猜坐标 ✓（无需改动）|
