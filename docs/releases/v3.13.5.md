# v3.13.5 — 定时任务板块修复：投递轮数硬上限 + 离线崩溃恢复 + 并发 + 导出

## 背景

定时任务（autotask）板块专项审查发现四处问题，本版按 H1→H2→M1→M7 修复。

## 修复

### H1 投递主路径轮数硬上限（成本硬伤）
- **根因**：离线路径有 RoundStarted 护栏（先 steer「请收尾」、超两轮强制中断），
  但投递到会话的**在线路径**完全裸奔 —— `AgentLoop` 明确「循环不设本地轮数上限」，
  无人值守时模型可无限跑轮烧钱。
- **实现**：`AgentRuntimeWire.RunRequest` 新增 `maxRounds`（跨进程透传，null=不设限）；
  模块侧 `AgentRuntimeRunExecutor` 在 `complete()` 的 onEvent 挂 `RoundStarted` 计数，
  与离线 `SimpleAutoTaskRuntime` **同一套护栏**（先 steer「请收尾」给两轮宽限，
  仍不收尾 `cancel()`）。
- **链路**：`SimpleAutoTaskRuntime`（有 `task.maxRounds`）→ `AutoTaskDispatcher`
  （register/enqueue/flush/tryDeliver 全部透传）→ `deliverAutoTaskPrompt` →
  `launchConversationRun` → `RunRequest`。普通对话/压缩/续跑/编辑重发不传
  `maxRounds`，行为不变。
- **readOnly 说明**：非只读任务本就在 `execute()` 闸门处被拒绝，不会进入投递；
  工具级裁剪未做 —— terminal/browser 工具读写兼备，裁剪会误伤只读任务的主用途
  （内存/性能检查依赖 terminal 读取），且与离线路径「引导式」语义保持一致。
  如需更硬的只读约束，可作为独立议题另行评估。

### H2 离线执行崩溃恢复
- **根因**：离线轮 `lastRunAt` 整轮跑完才写库，进程中途被杀（系统回收/崩溃）后无任何痕迹，
  叠加脚本标记残留 → 卡死或每次唤醒重跑双烧费。
- **实现**：离线轮开始前写「执行中」标记（`taskId|startedAt`，`in_progress.txt`），
  清除放在离线分支最后（覆盖跑轮+落库+导出+通知全窗口）。下次唤醒先按标记恢复：
  `lastRunAt >= startedAt` → 上一轮实际完成，只清残留标记；否则 → 真中断：
  记录结果并消费（一次性任务停用，杜绝无时间限制任务每次唤醒重跑；周期任务只推进
  `lastRunAt`，等下一次到点）。顺带删除死代码 `clearRunMarker`（按任务清，无人调用）。

### M1 并发读取入锁
- **根因**：`runnableBlocking()` 在 `synchronized(RUN_LOCK)` 之前读（锁外快照），
  并发唤醒可能两份就绪快照各跑一遍同一条任务。
- **实现**：读取移进锁内；崩溃恢复先于决策，被恢复停用的一次性任务不会被再次选中。

### M7 AutoTaskService 不导出
- **根因**：manifest `exported="true"` 与类注释「服务不导出」矛盾，任意应用可触发模型调用。
- **实现**：改 `exported="false"`（root 守护脚本 `am startservice` 不受影响）。

## 验证

- 编译通过；全量门禁 365 失败**全部为环境性失败**（363 Robolectric aarch64 + 2 DexKit
  基线），新增非环境失败 = 0。
- 守护脚本（不在仓库）标记语义依赖真机复核；崩溃恢复分支建议真机 kill 进程验证。
