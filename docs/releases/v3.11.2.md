# v3.11.2 — 参数卫生检查（XML 粘包残渣）+ OCR 定位协议

小修复：两道"让模型少走弯路、同时堵住执行面"的防护。

## 一、OCR 定位协议

`LOCATE_MISS` 曾被当成"改用目测"的许可：对目标只调用一次 locate、拿到 MISS 后即转目测，
对同一目标连点 4 次。（同类问题 2026-10-04 出现过一次，属反复模式。）

- **提示词**：改为明确重试协议 —— `LOCATE_MISS` 表示关键词与屏幕原文不符，应按返回里列出的
  可见文本改写成屏幕原文重查（最多两次不同关键词）；仍未命中才允许看截图，且**目测在同一目标
  上最多尝试一次**，失败必须停下向用户说明。
- **工具**：MISS 载荷新增「当前屏幕可见文本」候选（去重、限 12 条 × 24 字符），来源为**已经拿到的**
  OCR 文本与 UI 树节点，**零额外 OCR 成本**。

## 二、参数卫生检查

**问题（真机取证）**：模型把 tool call 写成 XML 风格并粘包，`action` 值成了
`exec><parameter = command>/tmp/ub 2>&1 | grep …`。落在**枚举字段**会被取值校验挡住（安全），
但若落到 `command` 这类**自由文本字段**，会被原样交给 shell 执行 —— 可能凭空创建或覆盖文件。

**修复**：在 `AgentToolCallValidator.validate`（所有工具调用的统一入口，`AgentLoop:383` 调用）
前置一道递归检查，参数值里出现明确粘包形态即拒绝并给对症引导：

| 标记 | 含义 |
|---|---|
| `</parameter>` | 闭合标签 |
| `><parameter ` | 粘包特征：前一个值 + 下一个参数标签 |
| `<parameter name=` | 参数标签头 |
| `</invoke>` / `</function_calls>` | 其它 XML 调用形态 |

**设计约束**：

- **不误伤**：只在明确粘包形态上触发。`grep '<parameter' config.xml`（含 `<parameter` 但缺闭合
  标签与粘包前缀）正常通过；`echo '<a>text</a>' > out.xml` 同样不受影响。
- **不做自动纠正**：绝不改写模型给的参数，只拒绝 + 引导重发，避免引入新的不确定性。
- **覆盖全部工具**：一处接入覆盖 150+ 工具的**全部字符串参数**（含嵌套对象与数组），
  而不是逐个工具打补丁。
