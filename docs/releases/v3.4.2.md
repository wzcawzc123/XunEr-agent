## Eta v3.4.2

本版收掉 v3.4.1 自身留下的两处尾巴：一是 `terminal` 的 `environment` 判定被收窄成了**大小写敏感**，
二是备份导出失败时会在目标文件里留下半份数据。

### ① `environment` 判定恢复大小写不敏感

v3.4.1 为让"模型没传 environment"不再被静默伪装成 android，在 `terminal` 工具层加了一道入参白名单。
但实现用的是**区分大小写**的字面比较（`!= "android"` / `!= "linux"`），
而底层 `RootShellTerminalController.normalizeEnvironment()` 一直是 `.lowercase()` 解析的 ——
两者不一致，导致模型写出 `"Linux"`、`"ANDROID"` 这类值时收到：

```
INVALID_TOOL_ARGUMENTS · environment 仅支持 android/linux，实际收到：Linux
```

而在 3.4.0 里同样的调用是正常执行的。现改为大小写不敏感，与底层对齐：

- 判定抽成 `isValidTerminalEnvironmentArgument(raw)`，用 `ignoreCase = true` 比较
- 空白仍视为"未提供"，按 android 执行并在结果里标注 `environment_source=default`（v3.4.1 的行为不变）
- 真正不可识别的值（如 `posix`）仍照旧拒绝，并回显收到的值与允许集合

同一处大小写疏漏还影响轨迹展示：`AgentTraceFormatter.terminalEnvironmentLabel()`
对 `"Linux"` 会错显成 "Android"。一并修正。

### ② 备份导出失败不再留下半份文件

v3.4.1 把备份导出改成流式写盘（修掉了 218 MB 数据集上的 `OutOfMemoryError`），
但失败语义随之改变：旧实现"先检查 64 MiB 上限再写"，超限时文件是空的；
流式实现"边写边检查"，超限时目标文件里**已经写入了最多 64 MiB 的截断 JSON**。

而 `DataBackupScreen` 的失败分支只弹一个 Toast，并不删除该文件 ——
用户可能在文件管理器里看到一份半截的备份并误以为导出成功
（导入时 JSON 解析会报错，因此不会静默损坏数据，但观感与预期不符）。

现在失败路径会删掉这次创建的文件。

### 验证

- **Windows 11 / JDK 25 / SDK 37**：1144 项，通过 1108，失败 36，跳过 2。
  与 **纯 v3.4.1 基线**（1139 项 / 36 失败 / 2 跳过）做**用例级集合差集**：
  **共同失败 36、回归 0、被修复 0** —— 失败集合完全一致，
  均为"Windows 作为测试宿主"的平台差异（pty / root shell / 盘符冒号 / 记忆文件存储等），在 Linux 上通过。
- 新增测试 `AgentTerminalEnvironmentArgumentTest`（5 条）：非法值拒绝、报错回显收到的值与允许集合、
  大小写放行、空白视为未提供、真未知值仍拒绝。
- 另有 `AgentTraceFormatter` 的标签修正，属纯展示层，无行为变更。
