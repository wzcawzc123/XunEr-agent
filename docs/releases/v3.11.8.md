# v3.11.8 — 工具调用格式错乱引导加固（全角 XML 粘包漏检 + 解析失败诊断 + 协议 input 保真）

## 背景

真机取证（2026-10-10）：工具调用出现大量 `INVALID_ARGUMENT` 失败，统一形态为
`arguments 的 action 值「exec><parameter＝command>F＝/data/adb/modules/...」`——**模型输出
全角等号（U+FF1D）的 XML 风格参数并粘包**。

全局审查（覆盖协议解析 → 参数校验 → 执行 → 结果 → 重试 → 模型引导 → schema 质量）定位根因：

1. **XML 粘包检测只覆盖半角形态**：`AgentToolCallValidator` 的 `xmlResidueMarkers`
   （`><parameter ` 要求半角空格、`<parameter name=` 要求半角）对全角等号 `＝` 全部漏检 →
   残渣落到 terminal 的 `action` 枚举校验 → 报泛化的「action 值不被接受；合法取值：…」→
   **模型看不到「你输出了 XML 标签」的引导，不知错在哪，反复以同样形态重试**（用户所见高频失败）。
2. **参数解析失败无诊断**：全角引号 / 截断 JSON / XML 全文 → 只报「参数不是有效的 JSON object」，无对症引导。
3. **Anthropic 协议 tool_use input 静默降级**：`parseJsonObject` 非 JSON → 空对象 `{}`，
   同一 run 后续轮次模型看到空 input 重复猜测参数。

上游对照（Mangi-11/Eta `AgentToolCallValidator`，348 行）：原版同为「审查-拒绝」架构，
但**拒绝信息是粗引导**（「不符合 anyOf 中的任何 Schema」），无 XML 检测、无字段清单、
无脱敏/退役引导——本 fork 的引导体系（XML 检测、分支标签、合法取值、字段清单、脱敏引导）
是 fork 独有的迭代资产（INVARIANTS F4），本轮是顺着该体系补漏。

## 修复

### 逻辑修复

1. **XML 粘包标记扩展**（`AgentToolCallValidator.xmlResidueMarkers`）：
   新增 `><parameter=`（半角无空格）、`><parameter＝`（全角等号，真机形态）、`<parameter＝`（全角无前缀）。
   **误伤保护不变**：`grep '<parameter' config.xml`（单引号前缀）仍不命中（反例测试锁定）。
   修复覆盖全部工具与三种协议（Chat/Responses/Anthropic 的 arguments 均为原文进入 validator）。
2. **参数解析失败诊断**（`validate()` 解析失败分支 → 新增 `malformedArgumentsGuidance`）：
   探测全角引号（U+FF02/201C/201D）→ 引导「改用半角双引号包裹」；XML 形态 → 复用 XML 引导；
   其余保留原文案。
3. **Anthropic tool_use input 保真**（`parseJsonObject`）：非 JSON 不再静默降级为空对象，
   回写为 `{"_eta_unparseable":true,"raw":"<原文（截断 2000 字符）>"}`，同一 run 后续轮次
   能看到原始参数而非空 input。拒绝路径不受影响（tool_calls arguments 本就是原文）。

### prompt 约束（引导层，有效性需真机反馈验证）

4. 系统提示追加一段：工具调用参数必须标准 JSON 与半角标点、禁止 XML 标签或全角符号；
   执行命令/文件操作前先确认目标路径与文件存在（mkdir/ls/stat 先行）；敏感工具脱敏参数
   不可原样重发、须重新取数。归 **prompt 约束**（引导层可被模型忽略，不称根因修复）。
