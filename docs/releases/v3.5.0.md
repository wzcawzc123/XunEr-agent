## Eta v3.5.0

功能版本：**locate_on_screen 设备侧定位工具（M2.1）** —— 坐标精度从"模型目测"切换到"程序查表"，修复方案核心项落地。

### 背景（2026-10-04 真机取证，conv-e7b0a537）

v3.4.9 引导层实测：升级逻辑按设计触发（两次目测未命中后切像素分析），但**首中率未改善**——
稀疏树场景（KSU Compose 列表未暴露子项）模型目测 4 连不中，系统性偏差 ~0.96
（估 y2716/2740，真值 2857），像素分析脚本也找错中心，最终靠裁剪放大才命中，
一个按钮耗掉 ~50 条消息。结论：**目测路径无解，定位必须程序化**。

### 改动

**新工具 `locate_on_screen`（逻辑修复·核心）**
- 按 query（text/desc/viewId 子串，空白分词 AND，大小写不敏感）在当前屏幕节点快照里
  精确定位，返回 screen 坐标 bbox + center + 匹配得分；
- 每次调用重新抓取快照，不依赖旧观察；与 observe_screen 同一套发布与新鲜度记账，
  返回结果可直接 `tap(coordinate_space=screen)` 或用 index+observation_id 调 `tap_element`；
- 结构化错误码 `LOCATE_MISS` / `LOCATE_UNAVAILABLE`，禁止猜坐标兜底。

**引导（prompt 约束，非根因修复）**
- 稀疏树提示改为 locate 优先；像素分析 SOP 降级为 LOCATE_MISS 后的后备
  （6%/PIL 文案暂保留，按方案时序等 OCR 通道落地后删除，v3.5.1）。

**M0 固化（文档+测试锁）**
- 新增 `docs/INVARIANTS.md`：F1–F7 七项修复的源码锚点/测试一对一映射，
  含 2 条如实记录的缺口、测试门禁规则（本地=非环境失败相对基线为 0，禁"全绿"目标）、
  Changelog 三分类规范（prompt 约束禁止写成根因修复）；
- 补 F7 测试锁 `AgentImageToolsTest`（read_image 必须带 image_width/height 与坐标警告）。

### 已知限制

- locate 目前只有树匹配通道：目标不在树里（如 Compose 列表不暴露子项）返回 LOCATE_MISS，
  回落既有像素分析兜底；OCR 通道在 v3.5.1。
- `AgentLocalToolsLocateTest`（4 例）与 `AgentImageToolsTest`（2 例）为 Robolectric 用例，
  本地 aarch64 环境失败属预期，由 CI 侧验证。

### 验证

- `ScreenLocatorTest` 7 例本地全绿；
- 全量 1247 例：304 失败 = 302 环境类（Robolectric/DexKit/conscrypt）+ 2 已知 DexKit，
  **新增非环境失败 0**，门禁通过。
