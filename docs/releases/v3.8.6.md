# v3.8.6 — 上下文成本护栏

小修复：**修复长会话上下文成本失控（真机 HTTP 402）**，并补上三道护栏。

## 背景（真机事故，2026-10-07）

会话 `conv-3d2f1ce4`（标题 XunEr-agent）在使用中额度瞬间耗尽并报 HTTP 402。DB 实测：

| 指标 | 数值 |
|---|---|
| 消息 / 工具调用 / 用户回合 | 4253 / 1723 / 96 |
| 813 轮累计 input tokens | **289,405,760** |
| 缓存命中率 | 97.0%（2.807 亿命中） |
| 单轮 input 峰值 | **749,916** |
| 压缩后基线 | 61,945 ~ 73,252 |
| 压缩事件 | 7 次，末段 4233 / 4244 / 4248 / 4252 连续发生，夹着两次 `runtime_failed`(402) |

两个容易被忽略但很关键的测量结论：

- **命中率不是瓶颈**：未命中的量只占 3%，却占总费用的 **23.7%**（按命中≈1/10 价折算）。真正要治的是「击穿次数」。
- **压缩 = 缓存击穿**：压缩改写历史前缀，压缩后首轮命中率从 99.9% 掉到 **9.4%**（全价重算）。所以压缩本身必须「划算」。

## 修复（三处根因）

1. **触发线加上限**：`triggerTokens(window) = min(window × 0.75, 200_000)`。
   100 万窗口原先要装到 75 万才压缩，等于没有护栏；大窗口模型上「还装得下」不等于「应该装满」。
2. **压缩失败熔断**：失败分支原先既不重置 `inputTokens` 也无状态，而每轮 loop 都会尝试压缩 ——
   额度不足时退化为「每轮再付一次全量摘要请求」的风暴。现在失败一次即停（本 run 内），
   `force`（手动压缩 / 收尾）不受限，跨 run 自动恢复，兜底交给既有硬裁剪。
3. **压缩降幅门槛**：压缩产物若仍 ≥ 压缩前的 80%，判 `CONTEXT_NO_REDUCTION` 并保留原文，
   杜绝「压完立刻再压」的抖动式重复计费。

## 测试与验证

- 新增 `AgentContextCostGuardTest`（4 例：上限、熔断、force 例外、降幅门槛）。
- 更新 `AgentContextRecoveryTest` 触发线用例（675,000 → 200,000）。
- 相关测试全绿：`AgentContextCompactionTest` 17、`AgentContextRecoveryTest` 14、`AgentContextCostGuardTest` 4。
- 本机 aarch64 上 Robolectric 用例因 `DefaultNativeRuntimeLoader` 无法加载而失败（环境性，与本次改动无关），以 CI（x86_64）为准。

## 行为变化（升级须知）

- 长会话会更早触发压缩：默认压缩线从「窗口×0.75」降到 **最多 20 万 tokens**。
- 单次压缩必须至少缩小 20%，否则视为无效（不提交、不改写上下文，并触发熔断）。
