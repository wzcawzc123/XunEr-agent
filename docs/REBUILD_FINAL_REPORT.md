## 五、关键工程决策（可复用的经验）

1. **符号级对比优先于整文件 diff**——`comm` 对比 fun/val 集合，一眼看出「严格超集」与「双方各有独有」。记忆页 8 个独有符号/上游 0 → 整份换安全；AgentLoop 双方各有独有 → 只能补差异。
2. **契约测试当探针**——误把图片降级上限加在 `attachmentProfile` 时，两条红测试立刻指出「该路径要求保持原尺寸」。
3. **只追加 DAO/枚举，不整份换**——ConversationDao 上游独有 16 个函数，整份换必丢。
4. **新增工具必须同步三处**——需求登记、精确工具集合断言、图标映射，少一处 CI 就红（androguard 踩过，fork 当年也踩过）。
5. **改 Compose 取资源方式必须跑 lint**，只跑编译不够（`LocalContextGetResourceValueCall` 是 error 级）。
6. **判定表的基准要换**——不只问「上游有没有」，还要问「当前分支已落地多少」，后者直接告诉你剩余工作的真实位置。

## 八、以后怎么合并上游

```bash
git fetch upstream && git rebase upstream/main
```

实证：42 个补丁 rebase 零冲突。只要守住「补丁要薄」（在上游实现上加分支，不整文件覆盖），冲突面永远可控。真正难合并的只有两件事：整文件替换上游代码、在上游频繁改动的文件里做大改动。
